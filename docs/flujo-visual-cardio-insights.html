2. Lo que hace la interfaz actual

Al autenticarse, React guarda el token y arma un tablero con llamadas protegidas. Esto representa el recorrido que hoy puede ejecutar una persona desde la UI.

1
Login: envía usuario/clave a POST /auth/login y recibe el access_token JWT junto al perfil.
2
Carga inicial o aplicar filtros: llama en paralelo a /dashboard/summary, /kpis/query y dos variantes de /analytics/query (tabla y ranking).
3
Render: muestra tarjetas de situación, tendencias, tabla analítica y top ranking a partir del JSON recibido.
4
Vista Cubo: al entrar a “Cubo” o crear consulta, llama POST /analytics/query con dimensiones y agregación elegidas.

5. Lenguaje natural: de frase a respuesta

No es un modelo generativo: hoy el servicio interpreta la pregunta mediante reglas de palabras clave y reglas temporales JSON. Luego arma un request estructurado a un endpoint que ya existe.

Pregunta“¿En qué mes estuvimos peor con las demoras?”
→
NormalizarMinúsculas y equivalencias sin tildes.
→
DetectarIntent, métrica, granularidad y fechas.
→
Elegir endpointKPI trend o analytics ranking.
→
Ejecutar datosRepositorio mock/MySQL.
→
ExplicarPayload, supuestos y resultado.

A. Tendencia

Si pregunta “cómo viene”, “evolución” o menciona una métrica sin pedir top, deriva a:

POST /kpis/query

{
  "kpi_keys": ["avg_wait_days"],
  "granularity": "month",
  "filters": [
    {"key": "date_from",
     "values": ["2026-01-01"]},
    {"key": "date_to",
     "values": ["2026-12-31"]}
  ]
}

B. Ranking o pico

Si detecta “top”, “mayor”, “peor”, “pico” o preguntas “en qué mes/día”, deriva a:

POST /analytics/query

{
  "widget_type": "ranking",
  "metric_key": "avg_wait_days",
  "granularity": "month",
  "limit": 5,
  "filters": [...]
}

C. KPI no existente

Para casos previstos como “espera máxima” o “volumen total”, propone o crea un KPI dinámico.

Modo inicial: human_approve

{
  "auto_kpi": {
    "created": false,
    "status": "pending_approval",
    "requires_approval": true

6. Cómo nace un KPI nuevo

El KPI Designer permite ampliar métricas sin editar pantallas. En MySQL la definición puede persistir; en modo mock queda en el registro en memoria del proceso.

Creación manual
1. Abrir /kpi-designer/ui y pegar JWT
2. Definir nombre, descripción, granularidad y SQL
3. El SQL debe devolver period y value
4. POST /kpi-designer/create genera, registra y valida
5. Consultar la key en /kpis/query
⇄
Desde lenguaje natural
1. La pregunta pide una métrica no mapeada pero prevista
2. El planner genera un candidato de KPI y SQL
3. suggest_only, human_approve o auto_create
4. Si se aprueba, registra y valida la nueva métrica
5. Reejecuta automáticamente la consulta original

suggest_only

El sistema muestra el candidato, pero no crea nada.

human_approve

Modo por defecto. Exige approve_auto_kpi=true y rol autorizado.

auto_create

Crea y valida automáticamente, útil para prueba controlada.

7. De dónde salen los datos

Modo desarrollo

REPOSITORY_BACKEND=mock

  • Usuarios demo y series fijas.
  • Permite desarrollar UI sin base instalada.
  • KPIs dinámicos viven en memoria y devuelven serie simulada.
Modo datos reales

REPOSITORY_BACKEND=mysql

  • Ejecuta SQL sobre base INCC.
  • Usa tablas como flow_coordina, dat_cirugia, call_ptcamaster y flow_procedimientocardiologia.
  • KPIs dinámicos se guardan en cardio_dynamic_kpis.
Mismo endpoint/kpis/query o /analytics/query

8. Guion de 60 segundos para el equipo

“Cardio Insights tiene una interfaz React que nunca consulta directamente la base. Primero el usuario se autentica y obtiene un token. Con ese token, la pantalla pide tarjetas, series de KPIs y analítica al backend FastAPI.”

“La API pasa por servicios y usa un repositorio que puede ser mock o MySQL; por eso desarrollamos sin base y luego enchufamos datos reales sin cambiar la forma de las respuestas.”

“Además existe una capa de lenguaje natural: toma una pregunta, reconoce métrica, período e intención, la convierte a una consulta estructurada y devuelve tanto el dato como la explicación de lo que interpretó. Esa API está lista; el cuadro de preguntas todavía debe conectarse en el frontend.”

“Cuando aparece una métrica nueva, KPI Designer permite definirla con SQL que devuelva período y valor; luego se registra y queda consultable como cualquier otra serie.”

Fuentes verificadas en el repositorio: frontend/src/App.jsx, backend/app/api/v1/*.py, backend/app/services/*.py, backend/app/repositories/*.py, backend/app/schemas/*.py, backend/app/core/config.py y backend/app/tests/test_api.py.
